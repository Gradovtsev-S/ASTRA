# Правила работы над репозиторием

## Распределение

| Ветка | Ответственный | Файлы |
|---|---|---|
| `feature/actuators` | Святослав | `firmware/src/actuators/*` |
| `feature/sensors` | Полина | `firmware/src/sensors/*` |
| `feature/logic` | Саша | `firmware/src/logic/handler.*`, `star_catalog.*`, `adapter.*` |

`logic/astronomy.*` это библиотека Astronomy Engine, её не редактируем.

Каждый правит только свою папку. Чужие файлы трогаем только по договорённости.

## Начало работы

```bash
git clone https://github.com/Gradovtsev-S/ASTRA.git
cd ASTRA
git checkout -b feature/<имя>
git push -u origin feature/<имя>
```

## Ежедневный цикл

```bash
git fetch
git merge origin/main          # подтянуть изменения других
# работа, затем:
git add <файлы>                # не `git add .`, чтобы не зацепить лишнее
git commit -m "feat(motors): add homing by Hall sensors"
git push
```

Подтягивай `main` раз в день-два, чтобы расхождения не накапливались.

## Формат коммитов

```
<тип>(<модуль>): <кратко, в повелительном наклонении>
```

Типы: `feat` (новое), `fix` (исправление), `refactor`, `docs`, `test`, `chore`.
Модули: `motors`, `laser`, `gps`, `gyro_accel`, `mag_compass`, `handler`, `adapter`, `catalog`, `config`, `main`.

Примеры:
- `feat(gps): parse NMEA from Neoway G7A`
- `fix(handler): wrap azimuth to 0..360`
- `docs: update README`

Один коммит - одно законченное изменение.

## Общие файлы

| Файл | Правило |
|---|---|
| `config.h` | у каждого своя секция, чужие секции не правим |
| `main.cpp` | в ветках не трогаем, собирается на этапе интеграции |
| `README.md`, `CONTRIBUTING.md`, файлы сборки | правит один человек, остальные просят |
| `secrets.h` | не коммитим (в `.gitignore`), у каждого свой |

## Заголовки - это контракты

`.h` файлы модулей описывают, как модули общаются между собой. Менять их в своей ветке нельзя.

Если интерфейс нужно изменить:
1. Предупреди остальных в чате.
2. Внеси правку отдельным коммитом в `main` (через PR).
3. Все подтягивают `main` в свои ветки.

## Своя ветка должна собираться

Чужие модули в ветке заменены заглушками из `main`. Перед пушем проверь, что проект собирается.

Тестируем независимо:
- актуаторы: скетч, который крутит моторы и включает лазер;
- датчики: скетч, который выводит показания в Serial;
- логика: `handler_calculate` вызывается на компьютере с входными данными, заданными вручную.

Тесты называем по модулю и кладём в `firmware/test/`.

## Pull request

1. Ветка готова и собирается, актуальный `main` влит в неё.
2. Создай PR в `main` с описанием: что сделано, как проверено.
3. Один из остальных просматривает PR и одобряет.
4. Вливаем через merge (без force-push в `main`).

## Интеграция

После вливания всех трёх веток:
1. Создаём `feature/integration`.
2. Собираем в `main.cpp` цепочку: датчики -> `adapter` -> `handler` -> моторы.
3. Проверяем на железе без лазера: сравниваем углы с реальным положением звезды.
4. Лазер включаем в последнюю очередь, только при `status == Ok` и достигнутой цели.

## Безопасность лазера

Лазер 5 мВт, класс 3R: не направлять на людей, транспорт и самолёты. При любых сомнениях в данных датчиков лазер должен быть выключен. Первые запуски делаем без лазера.

## Переносы строк

Предупреждение git `CRLF will be replaced by LF` на Windows безвредно. Чтобы оно не появлялось, в `.gitattributes` должна быть строка:

```
*.h *.c *.cpp *.md text eol=lf
```
